# Integration checklist

Every external dependency, what it needs, where the secret goes, which flow it affects, whether it blocks live use, and how to verify it. **State** is one of: verified sandbox, verified live, simulated, unverified (adapter written to the documented contract but never exercised with a credential).

| Dependency                                       | Provider and setup                                                                                                   | Variables (server-only unless noted)                              | Flow affected                                               | Blocks live use                                            | State                                                   | Verify                                                                                                                             |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| PayPal Orders, Payments, Order Tracking          | [PayPal Developer dashboard](https://developer.paypal.com/dashboard/) → REST app, sandbox client id and secret       | `PAYPAL_MODE=sandbox`, `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET` | approval, hold, capture, void, reauthorize, tracking        | yes                                                        | simulated                                               | `npx tsx scripts/paypal-smoke.ts` runs order → authorize → partial capture → void against the sandbox and prints each id           |
| PayPal Webhooks                                  | Same app → Webhooks, events PAYMENT.AUTHORIZATION._, PAYMENT.CAPTURE._, CUSTOMER.DISPUTE.*; needs a public `APP_URL` | `PAYPAL_WEBHOOK_ID`                                               | reconciliation speed (polling covers correctness)           | no                                                         | unverified                                              | `npx tsx scripts/register-webhook.ts`, then trigger a sandbox capture and watch `paypal_events`                                    |
| PayPal Disputes (sandbox-only create/adjudicate) | Same app; a sandbox Personal account for the buyer side                                                              | `PAYPAL_BUYER_EMAIL`, `PAYPAL_BUYER_PASSWORD` (scripts only)      | dispute open, evidence filing, adjudication                 | no (production disputes are opened by the buyer in PayPal) | simulated                                               | Flow D in `npm run test:browser` with `PAYPAL_MODE=sandbox`                                                                        |
| Anthropic (compiler and examiner)                | [console.anthropic.com](https://console.anthropic.com/) → API key                                                    | `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`                            | brief → test; judgement lines                               | no (starter tests and buyer decisions take over)           | simulated when `EXAMINER_MODE=simulated`, off otherwise | `npm run eval` prints agreement, abstention rate and false releases on 30 labelled cases                                           |
| Resend (mail)                                    | [resend.com](https://resend.com/docs/api-reference/emails/send-email) → API key, verified sending domain             | `MAIL_PROVIDER=resend`, `RESEND_API_KEY`, `MAIL_FROM`             | every notification and reminder                             | no (simulated outbox otherwise)                            | unverified                                              | Send a proofhold with your own address as the buyer; Settings → Outbox shows `sent` with a provider id, or `failed` with the error |
| Postgres                                         | Render blueprint provisions it; any Postgres 14+ works                                                               | `PROOFHOLD_STORE=postgres`, `DATABASE_URL`                        | all storage                                                 | no (SQLite locally)                                        | unverified                                              | `npm run build && npm start` against the database, then `GET /api/health`                                                          |
| Scheduler (external)                             | Any cron that can POST                                                                                               | `PROOFHOLD_SCHEDULER=external`, `TICK_SECRET`                     | windows, reminders, reauthorization, expiry, reconciliation | no (inline by default)                                     | verified locally (inline)                               | `curl -X POST -H "x-tick-secret: …" $APP_URL/api/internal/tick` returns the pass report                                            |

Public configuration (safe in a client bundle or a blueprint): `APP_URL`, `PAYPAL_MODE`, `MAIL_PROVIDER`, `ANTHROPIC_MODEL`, `PROOFHOLD_SCHEDULER`, `DEMO_SILENCE_MINUTES`. Everything else is a server-only secret: set it in the host's secret store, never in `.env.example`, a commit, a log or a screenshot.

When a credential arrives: set it in `.env.local` (never paste it into chat), run the verify step in the table, record the result and date in `docs/acceptance-matrix.md`, and change the State column here. A row stays simulated or unverified until its verify step has actually passed.
